# [Troubleshooting] LLM 데이터 전송 형식에 따른 토큰 효율성 분석

## 1. 개요 (Overview)

- **문제 정의**: OpenAI API 호출 시 전송하는 GitHub 활동 데이터의 양이 많아 토큰 소모가 큼. 이를 최적화하기 위해 JSON 형식을 YAML로 변경했을 때 실제 토큰 절감 효과가 있는지 검증이 필요함.
- **배경 상황**: 
  - 프로젝트: `git-mate-backend`
  - 관련 컴포넌트: `src/analysis/llm-provider.service.ts`
  - 환경: OpenAI GPT-4o (`o200k_base`) 및 GPT-4 (`cl100k_base`) 모델 사용

## 2. 접근 방법 (Approach)

- **원인 분석**: 
  - 현재 `JSON.stringify(data)`를 사용하여 컴팩트한 JSON 형식으로 데이터를 전송 중임.
  - JSON의 구조적 기호(`"`, `:`, `{`, `}`, `,`)가 토큰을 많이 소비한다는 가설이 제기됨.
- **가설 설정**: 
  - **가설**: YAML은 따옴표와 중괄호를 줄이고 개행과 들여쓰기를 사용하므로, 텍스트가 많은 데이터 구조에서 토큰을 절약할 수 있을 것이다.
  - **검증 과정**: 실제 GitHub PR 데이터를 샘플링하여 `js-tiktoken` 라이브러리를 통해 `o200k_base` 및 `cl100k_base` 토큰 수 비교 측정.

## 3. 해결 방안 (Solution)

- **조치 사항**: 
  - 비교 분석 스크립트 실행 결과, **명시적인 코드 수정은 진행하지 않기로 결정**.
  - 현재의 컴팩트 JSON 형식을 유지하는 것이 토큰 효율성 측면에서 더 유리함을 확인.
- **해결 근거**: 
  - **YAML의 오버헤드**: YAML은 구조를 위해 행마다 들여쓰기(Indentation)와 개행(Newline)을 소모하며, 이는 JSON의 쉼표나 괄호보다 더 많은 토큰을 소모함 (본 실험 데이터 기준 약 5% 증가).
  - **토크나이저 최적화**: OpenAI의 BPE(Byte Pair Encoding) 알고리즘은 일반적인 JSON 패턴에 이미 최적화되어 있어, 따옴표와 콜론이 결합된 형태를 효율적으로 인코딩함.

## 4. 결론 (Conclusion)

- **결과 검증**:
  - `o200k_base` 측정 결과: JSON(972 tokens) vs YAML(1023 tokens) → YAML이 약 5.25% 더 많은 토큰 사용.
  - `cl100k_base` 측정 결과: JSON(1255 tokens) vs YAML(1314 tokens) → YAML이 약 4.70% 더 많은 토큰 사용.
- **재발 방지**: 
  - 단순히 "문자 수"가 줄어든다고 해서 토큰 수도 줄어드는 것은 아님을 유의해야 함.
  - 향후 데이터 전송 최적화 시, 특정 형식(YAML, XML 등) 도입 전 반드시 실제 토크나이저를 통한 벤치마킹을 선행할 것을 제언함.
